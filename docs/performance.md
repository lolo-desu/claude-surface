# 0.10.19 性能调优

开发环境安装了 GoogleChrome/modern-web-guidance-src 对应的官方发行技能：

```sh
DISABLE_TELEMETRY=1 npx --yes skills add GoogleChrome/modern-web-guidance --agent codex --global --yes
```

技能安装在开发用户的 `~/.agents/skills/modern-web-guidance`，不作为扩展的运行依赖。当前技能版本 `2026_11_09-5bcc021b`，官方发行仓库检查时 HEAD 为 `4dd968349e54ca45a05dd5c818fb035c9054b022`。检索并阅读 `performance`、`break-up-long-tasks`、`defer-rendering-heavy-content` 等指南；实际采用 `performance` 的事件合并建议，并按剖析结果减少同步渲染量和重复扫描。其他指南用于评估方案，本版未引入 `scheduler.yield()` 或 `content-visibility`，也未改写酒馆私有渲染器或全局浏览器 API。静态 legacy-scan 未检出问题，该扫描仅覆盖指南的一小部分，不能代替运行时测量。

剖析发现，原生 `printMessages` / `redisplayChat` 在一次任务中解析整批消息；随后大量 DOM 与 class 变化也触发原生键盘控件观察器的可见性检查，增加布局开销。性能模式通过缩小原生显示窗口同时减少这两部分工作；扩展自身的局部刷新则减少额外的扫描与写入。

## 酒馆性能模式

默认关闭。管理原生 `power_user.chat_truncation`：每批最多显示 50 条，保留原本更小的正数；原生 0（全部显示）在启用期间按 50 处理。酒馆仍然负责解析、渲染、事件、编辑、生成和加载更早消息，完整 `chat` 数组与保存内容保留。显式指定条数的原生命令不被拦截。

原始显示条数和应用值一起保存在扩展设置 `nativePerformanceRestore` 中。重新加载时仍可恢复；关闭时只恢复仍属于扩展的应用值。外部程序或用户改变显示条数时，保留最新选择；原生数字框通过 jQuery 合成输入提交的情形也会被识别。切换开关不重载消息，所以当前编辑草稿、生成状态和阅读位置得以保留。

manifest 的 `disable` / `delete` hooks 在支持的酒馆版本中恢复设置，并关闭模式以避免保存事件重新启用。旧版本忽略 hooks 或直接删除扩展文件时，缺席的代码无法执行恢复；请提前关闭模式，或自行调整酒馆显示条数。

兼容风险主要来自第三方扩展依赖一次性显示全部消息或较大的 DOM 窗口。模式不消除网络读取、JSON 解析和模型请求耗时，也不能保证每条复杂消息的原生渲染小于 50ms。

## 扩展自身的增量更新

- 原生设置：按变更节点处理滑块、世界书状态及 Select2 控件，合并同一帧的重复区域；显式刷新、布局切换和停用仍完整协调原有状态。
- 相同滑块进度不重复写入样式，世界书属性仅在变化时写入。
- 消息追加／移除只刷新当前聊天概要，不再生成整套角色目录与侧栏列表。原生设置、人设、模型和聊天选择事件仍刷新列表；同帧的完整刷新请求不会被局部刷新覆盖。

## 可复现验证

测试需要本地 SillyTavern 1.19.0、Playwright 和对应浏览器；请求路由使用待测扩展源码，并拦截设置／聊天／角色变更，使用合成聊天与角色数据。性能夹具对后台分词请求提供固定响应，以排除分词器资源和网络依赖；测试覆盖渲染与交互，不验证真实模型生成或分词结果。

```sh
node --test tests/*.test.mjs
node tests/native-performance.browser.mjs
node tests/native-performance-compat.browser.mjs
node tests/native-ui-performance.browser.mjs
node tests/context-performance.browser.mjs
```

可通过 `CU_SOURCE`、`CU_TEST_URL`、`CU_PLAYWRIGHT_MODULE`、`CU_CHROMIUM_EXECUTABLE` 指定源码、服务器和测试依赖。WebKit 使用 `CU_ENGINE=webkit`、`CU_WEBKIT_EXECUTABLE`。`CU_PERF_REPEAT=3` 重复性能场景；`CU_PERF_QUICK=1` 省略开销较大的全部显示场景。时间测量应在无其他浏览器负载的独占窗口中进行，不使用 CPU 采样时的数据与采样结果混比。

Linux WebKit 回归不能代替 iPhone Safari 或添加到主屏幕后的实机验收。

## 本次测量结果

2026-11-14 04:31:33–04:36:25 UTC，在无其他活动浏览器的独占窗口，对同一份冻结源码执行 Chromium 156.0.8078.79 与 Linux WebKit 27.2 测试。每种场景重复三次，表中为打开聊天到消息装饰、底部定位完成的中位数。所有场景的完整聊天均为 1000 条，开启模式后显示最近 50 条，可继续加载旧消息。

| 浏览器 | 原生窗口 | 关闭模式 | 开启模式（50 条） | 耗时减少 |
| --- | --- | --- | --- | --- |
| Chromium | 默认 100 条 | 1783ms | 962ms | 46.0% |
| Chromium | 1000 条 | 18230ms | 997ms | 94.5% |
| WebKit | 默认 100 条 | 779ms | 470ms | 39.7% |
| WebKit | 1000 条 | 4885ms | 482ms | 90.1% |

Chromium 每次打开过程最长任务的中位数：默认 100 条场景从 497ms 降至 265ms，1000 条场景从 5273ms 降至 290ms。WebKit 不支持此处使用的 Long Tasks API，因此不将缺失数据记为 0。1000 条显示场景的聊天 DOM 元素从 81000 个降至 4051 个；完整聊天数组保留 1000 条。

扩展局部刷新计数测试使用 1000 条世界书条目：无关设置变化从访问 1000 个滑块、重写 2000 次属性，降到访问 0 个滑块和世界书控件。单个新增滑块访问 1 个，新增状态字段访问 1 个；重复或嵌套的待处理区域不会反复访问同一控件。1200 个角色的测试中，追加消息与加载旧楼层均不重建角色目录，流式正文不触发上下文更新。

补充万层聊天检查在两引擎中均通过：完整保留 10000 条消息，初始显示最近 50 条，加载更早消息后显示 100 条，阅读锚点偏差均为 -0.25px。该补充检查仅作为功能验证，不纳入上述计时。单元测试 123 项通过；设置局部刷新每引擎 28 项、上下文刷新每引擎 11 项、原生兼容交互每引擎 16 项及冷启动生命周期每引擎 4 项均通过。

这些结果来自合成数据与本机浏览器，不代表所有设备或网络条件。较大的收益来自缩小原生显示窗口；同时显示大量消息、真实模型生成和真实 iPhone 的性能需要分别评估。先前使用未固定后台分词响应的尝试已排除，表格只使用相同固定分词夹具的完整 36 个样本。
