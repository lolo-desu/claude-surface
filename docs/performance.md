# 0.10.20 性能模式增强

本版仅发布到 `unstable`，性能模式继续默认关闭。上一版的测量和安装指导保存在 [0.10.19 记录](performance-0.10.19.md)。

## 开启后的行为

- 原生消息窗口从最多 50 条缩小至最多 25 条，原本更小的正数继续保留。完整聊天数组、模型上下文和保存内容保留，旧消息继续通过酒馆原生入口加载。
- 支持的宿主将 `streaming_fps` 限制到最多 10；原本更低的值保留。生成片段、事件和最终文本继续全部接收，仅减少正文／思考的显示刷新。原生刷新器在开始生成时读取频率，因此从下次生成生效。
- 暂时关闭本扩展的毛玻璃、透明度、背景模糊及装饰动效，保留背景图片和变暗程度。保存的四项效果偏好不变，关闭模式后恢复；被临时覆盖的滑块会禁用并显示说明。
- 六个思考操作按钮使用共享 CSS 遮罩，减少空思考框也附带六棵 SVG 子树的开销。第三方图标与子节点不被覆盖，不支持遮罩时保留原 SVG。原生按钮、委托点击、可访问名称和确认弹窗保持生效。
- 对已经加载的大量消息，只分片转换图标；每片最多 40 条、目标预算 8ms，片间交还主线程。快速切换模式会取消旧任务。新消息继续按原有增量处理，不为切换模式重做全套头像装饰。
- 图标变动使用生成节点及所属控件记录判定，只跳过自有的添加和已释放图标的移除，避免再触发消息装饰。外部删除当前图标、混合文本／第三方节点和控件替换仍正常处理。

## 设置与错误保护

显示条数和刷新频率各自保存 `original` / `applied` 记录，关闭或支持的生命周期 hooks 按所有权恢复。旧版的 `applied:50` 记录会迁移到 25，并保留真正的原显示条数；用户手动设置的 50 不会被误当成旧版本的应用值。原生滑块和数字框经 jQuery 提交的新选择也会被保留。

宿主的原生流式错误路径会跳过最终刷新，降低频率可能扩大尚未持久化的尾部。性能模式对当前生成对象附加局部保护，在原生错误处理前同步补齐最后收到的正文、思考和当前 swipe，再调用原错误处理一次。正常完成、用户停止、继续生成仍使用原生流程；`MESSAGE_RECEIVED`、`CHARACTER_MESSAGE_RENDERED`、`IMPERSONATE_READY` 保持各生成类型的原生数量，有待完成的思考会按原生处理完成并发出相应通知。即使中途关闭模式，已经开始的低频生成仍保留这份错误保护；结束后释放。缺少必要宿主 API 时不降低原生刷新频率。

保护仅使用当前生成对象及公开的宿主帮助函数，不替换全局浏览器 API、fetch、原型或酒馆源文件。对聊天标识、消息对象、DOM 及当前生成对象进行身份检查，避免迟到的错误写入另一个聊天。

旧版酒馆可能忽略禁用／删除 hooks，直接删除目录也不能运行恢复代码；请在此类移除前关闭模式，或手动恢复原生显示条数和刷新频率。依赖完整页面 DOM 或高频显示回调的第三方扩展可能需要关闭此模式。

## Modern Web Guidance

本轮重新检索并阅读 `performance`、`break-up-long-tasks`、`defer-rendering-heavy-content`。

- 应用 `performance` 的限频和减少 DOM 工作建议：降低原生显示更新次数、减少 SVG 子树、精简效果，并用独立的相同消息窗口场景区分各项收益。
- 应用 `break-up-long-tasks`：图标转换按数量及时间预算分片，优先 `scheduler.yield()`，Safari 缺少此 API 时使用 `setTimeout(0)`，不额外引入 polyfill。
- 实验评估过 `content-visibility:auto`，但未发布：200 条富文本消息的重复布局实验中 Chromium 中位数约 199.6→94.1ms，WebKit 149.5→159ms，且旋转后的缓存高度可能造成大幅阅读位置偏移。该实验不能证明 iOS 用户获益，因此保留原有布局。

## 验证方式

本地 SillyTavern 1.19.0、Chromium 与 Linux WebKit，使用合成聊天、固定分词响应，拦截设置／聊天／角色写入及真实模型请求。测试原生 `StreamingProcessor`，由受控生成器提供全部片段；不验证真实模型和分词器的正确性。

```sh
node --test tests/*.test.mjs
node tests/native-performance.browser.mjs
node tests/native-performance-compat.browser.mjs
node tests/native-streaming-performance.browser.mjs
node tests/performance-icons.browser.mjs
node tests/performance-effects.browser.mjs
CU_BASELINE=/path/to/0.10.19 node tests/aggressive-performance.browser.mjs
```

通用参数包括 `CU_SOURCE`、`CU_TEST_URL`、`CU_PLAYWRIGHT_MODULE`、`CU_CHROMIUM_EXECUTABLE`。WebKit 使用 `CU_ENGINE=webkit`、`CU_WEBKIT_EXECUTABLE`。聊天比较的基线目录必须明确提供，避免误比较其他版本；`CU_DIAGNOSTICS=1` 才会启用额外原生观察器计数，正式计时关闭该选项。流式重复测量可用 `CU_STREAM_CASES=paced CU_STREAM_REPEAT=3`，保留相同的已加载 50 条消息，排除窗口缩小的影响。

Linux WebKit 不能代替实际 iPhone Safari／添加到主屏幕后验收；合成测试不能推断所有设备、真实模型或网络条件。视觉效果关闭的检查验证样式、配置和布局，不声称具体 GPU 节省幅度。

## 回归结果

157 项单元测试通过。原生生成器在两引擎中均通过正常／继续／停止／淡入／断流／纯思考断流／生成中切换模式，以及实际 swipe 和 impersonate 类型的补充检查；基础及类型检查每引擎合计 26 个受控场景。最终代码另通过每引擎 16 项错误专项回归（与前项重叠），包含工具占位先隐藏、末尾正文或思考尚未刷新的两种情况。错误保护在原生错误处理开始前保留最新正文、思考、当前分支或用户输入草稿，并按原生工具占位规则同步显隐。上述三种消息／草稿事件维持各类型的原生数量，思考完成通知则根据修复后的状态发出。

500 条已显示消息的分片切换检查保留 35000 字草稿、同一编辑器、光标、焦点、阅读位置和原生消息 DOM。加入自有变动判定后，相同测试的额外完整消息装饰从 500 次降为 0 次，Chromium 与 WebKit 均通过；外部变动仍需正常响应。视觉效果检查中，四种设计、手机和桌面的布局／阅读锚点偏差均为 0px；393px 和 320px 实际外观页的滑块禁用／恢复、变暗调节和动效切换通过，长提示未横向溢出。

两引擎各通过 53 项图标与切换检查，以及 33 项原生设置／生命周期检查。最终万层功能检查完整保留 10000 条消息的首尾内容，普通聊天、群聊、重新加载及设置恢复均通过；显示 25→50 条旧消息时，两引擎阅读锚点偏差均为 -0.25px。这些压力检查不纳入计时结论。

## 导航测量

旧版 0.10.19 性能模式与新版的同一份 1000 条合成聊天，Chromium 156.0.8078.79、Linux WebKit 27.2，各场景三次，以下为打开中位数。独占窗口为 2026-11-14 08:39:05–08:44:41 UTC，无其他活动浏览器、CPU 采样或原生观察器包装。

| 场景 | Chromium 旧版→新版 | WebKit 旧版→新版 |
| --- | --- | --- |
| 默认性能窗口 50→25 条 | 1081→776ms（减少 28.2%） | 567→506ms（减少 10.8%） |
| 同为 25 条 | 765→780ms | 476→483ms |

同为 25 条时，未测得稳定的额外导航耗时收益；结构上的确定变化是聊天 DOM 从 2032 个减少至 1707 个（减少 16.0%），思考操作 SVG 从 150 个减少至 0 个。50→25 条场景的 DOM 为 4063→1707，收益包含缩小窗口，不能全部归因于图标。

导航数据来自最终工具占位断流显隐修复前的冻结源码；随后唯一的生产修改在断流错误分支执行，导航路径保持原样，并另做最终错误和生成回归。正式导航复测明确跳过旧消息累计及追加阶段；这些阶段以完整 500 条流程和专项计数测试验证功能。WebKit 不支持本测试使用的 Long Tasks API，缺失指标记为不可用。

## 生成测量

最终源码在 2026-11-14 08:56:12–08:59:54 UTC 的独占窗口中完成 12 个样本：两个浏览器各三组模式关／开，均保留相同的 50 条已显示历史，输入 90 个受控片段、最终正文 42090 字符。此处不包含显示窗口从 50 条减至 25 条的收益，但包含低频刷新、图标和精简效果的整体模式变化。

| 指标（三次中位数） | Chromium 关闭→开启 | WebKit 关闭→开启 |
| --- | --- | --- |
| 原生正文／思考处理调用次数 | 73→11（减少 84.9%） | 25→11（减少 56.0%） |
| 进度回调累计 await 墙钟时间 | 1821→234ms | 631→213ms |
| 受控生成完成时间 | 5148→1849ms | 1954→1744ms |

所有样本保留全部 90 个生成事件、完整最终正文、当前 swipe，且最终强制刷新各一次。回调时间包含 await 期间的经过时间，不是纯 CPU 时间；完成时间受控生成器的节奏和浏览器工作共同影响，不代表真实模型推理速度。此项只能说明该合成长文本负载下减少了昂贵渲染工作，不能直接推断所有真实模型或设备的提速比例。
